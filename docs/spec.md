# Specification: SchoolOS

## 1. 概要 (Overview)
- **課題:** スクール運営者は生徒の進捗・離脱リスク・デモグラ情報を横断的に把握する手段がなく、感覚的な運営になりがち。既存LMSは海外製で日本のスクール運営に最適化されていない。
- **解決策:** 8軸KPI分析とAIチャーン予測を備えた日本市場特化型LMSデモアプリ。スクール運営者に営業するためのデモとして、URLを共有して自由に触ってもらう形式。
- **対象ユーザー:** スクール運営者（営業先）。デモを通じて管理者・講師・生徒の3ロールの体験を提供する。
- **スコープ:** ローカル開発のみ（デプロイ・CI/CD構築は対象外）。

## 2. 競合分析 (Competitive Analysis)

### 主要競合サービス
| サービス名 | 特徴 | 参考にする点 | 差別化ポイント |
| :--- | :--- | :--- | :--- |
| Teachable ($29〜$309/月) | シンプルな立ち上げ、AI字幕生成、iOS/Androidアプリ | 素早い立ち上げ体験、AIツール活用 | ページビルダーが制限的、管理者分析が弱い、SCORM非対応 |
| Thinkific ($36〜$149/月) | メール自動化が強い、トランザクション手数料0%、一括登録 | メンバーシップ・一括管理機能 | モバイルアプリなし、生徒の詳細進捗分析が弱い |
| LearnWorlds ($24〜$249/月) | インタラクティブ動画、適応学習AI、ホワイトラベル | 動画内インタラクション、分析の充実度 | UIが複雑で初心者に不親切、Starterプランは$5/販売の手数料 |
| learningBOX (無料〜22,000円/月) | 日本語完全対応、4,500社以上導入、教材形式が豊富 | 日本市場での実績、テスト作成の多様性 | 企業研修向けでスクール特化ではない、UIがやや古い |
| Lernen（他社デモ） | スクール向けに特化 | スクール運営の基本フロー | 動画視聴位置追跡なし、デモグラ分析なし、KPI機能なし |

### テーブルステークス（必須機能）
- コース・カリキュラム管理（セクション/レッスンの階層構造、順序制御） — 全競合が実装
- 動画配信 + レジューム再生（視聴位置の記録と復帰） — 全競合が実装
- 生徒ダッシュボード（進捗率、完了状況の可視化） — 全競合が実装
- 課題提出・フィードバック機能 — 大半の競合が実装
- 管理者向け生徒一覧（検索・フィルタ・ソート） — 全競合が実装
- レスポンシブ対応（PC閲覧前提だがタブレット対応程度は確保） — 全競合が実装

### 差別化戦略
- **8軸KPIダッシュボード** — 年齢・性別・職業・住所・セミナー参加頻度・課題進捗停滞分析・課題完了日数・アクティブ状況を一画面で可視化。競合で本格対応しているサービスなし。営業デモの目玉機能
- **AIチャーン予測スコアリング** — ログイン頻度・課題提出間隔・セミナー参加率から離脱リスクをスコア化。競合で対応なし
- **セミナーハイブリッド管理** — オンライン/現地参加の選択と管理を統合。Teachableはライブ授業にZoom連携が必要
- **講師レビューワークフロー** — 課題提出→講師レビュー→フィードバックの一元管理。専用の管理画面を持つ競合なし
- **日本市場特化UI** — 日本のスクール運営者が直感的に使えるUI/用語設計

## 3. ユーザーストーリー (User Stories)

### 管理者ストーリー
- **US-1:** 管理者として、KPIダッシュボードで生徒全体の健康状態を一目で把握したい。なぜなら感覚ではなくデータに基づいてスクール運営を改善したいから。
- **US-2:** 管理者として、チャーンリスクが高い生徒を素早く特定したい。なぜなら離脱前に介入して退会を防ぎたいから。
- **US-3:** 管理者として、生徒の詳細情報（デモグラ・進捗・活動履歴）を確認したい。なぜなら個別対応の判断材料が必要だから。
- **US-4:** 管理者として、生徒一覧を検索・フィルタ・ソートしたい。なぜなら特定条件の生徒群を素早く見つけたいから。
- **US-5:** 管理者として、課題ファネルを見て「どのステップで多くの生徒が詰まっているか」を把握したい。なぜならカリキュラム改善の判断材料になるから。

### 講師ストーリー
- **US-6:** 講師として、未レビューの課題提出を一覧で確認したい。なぜなら対応漏れを防ぎたいから。
- **US-7:** 講師として、生徒の提出内容を確認し、フィードバックを記入・送信したい。なぜなら生徒の学習を前に進めるサポートをしたいから。

### 生徒ストーリー
- **US-8:** 生徒として、自分の進捗状況と次にやるべきことをダッシュボードで確認したい。なぜなら学習の現在地を把握して計画的に進めたいから。
- **US-9:** 生徒として、動画レッスンを前回の続きから再生したい。なぜなら毎回最初から探すのは時間の無駄だから。
- **US-10:** 生徒として、動画のチャプター一覧から見たい箇所に直接ジャンプしたい。なぜなら復習時に効率的だから。
- **US-11:** 生徒として、カリキュラムの全体像と自分の進捗を見たい。なぜならゴールまでの距離感を知りたいから。
- **US-12:** 生徒として、課題をテキストで提出し、講師のフィードバックを受けたい。なぜなら学習の質を高めたいから。
- **US-13:** 生徒として、セミナーにオンラインまたは現地参加で申し込みたい。なぜなら自分の都合に合わせて参加方法を選びたいから。

### 共通ストーリー
- **US-14:** デモ閲覧者として、ロールを自由に切り替えて管理者・講師・生徒それぞれの体験を確認したい。なぜなら導入後のイメージを掴みたいから。

## 5. 機能要件 (Functional Requirements)

### コア機能（v1 必須）

#### ロール選択・切替
- [ ] **REQ-1:** トップページにロール選択画面を表示し、管理者・講師・生徒の3つのカードから選択できる
- [ ] **REQ-2:** ヘッダーにロール切替ボタンを常設し、どの画面からでも別ロールに切り替えられる
- [ ] **REQ-3:** ロール切替時は各ロールの固定デモユーザーとして動作する（管理者: 田中管理者、講師: 佐藤講師、生徒: 山田太郎）

#### 管理者: KPIダッシュボード
- [ ] **REQ-4:** 8つのKPIサマリーカードを表示する（在籍生徒数、アクティブ率、課題完了率、平均課題完了日数、セミナー参加率、チャーンリスク高の人数、3ヶ月以内課題達成者数、新規入会者数）
- [ ] **REQ-5:** 年齢分布グラフ（棒グラフ）を表示する。集計: studentProfiles.ageを10歳刻みでGROUP BY
- [ ] **REQ-6:** 性別分布グラフ（円グラフ）を表示する。集計: studentProfiles.genderでGROUP BY
- [ ] **REQ-7:** 職業分布グラフ（棒グラフ / 横棒）を表示する。集計: studentProfiles.occupationでGROUP BY
- [ ] **REQ-8:** 地域分布グラフ（棒グラフ）を表示する。集計: studentProfiles.prefectureでGROUP BY
- [ ] **REQ-9:** セミナー参加推移グラフ（折れ線グラフ）を表示する。オンライン/現地の内訳付き。集計: seminarRegistrationsをmonth+attendanceTypeでGROUP BY
- [ ] **REQ-10:** 課題停滞箇所分布グラフ（棒グラフ）を表示する。集計: 各レッスンの未完了者数を集計し、停滞が多い箇所を可視化
- [ ] **REQ-11:** 課題完了日数ヒストグラム（棒グラフ）を表示する。集計: enrolledAtから最終課題completedAtまでの日数を分布化
- [ ] **REQ-12:** アクティブ状況グラフ（折れ線グラフ）を表示する。集計: activityLogsのLOGINタイプを週単位で集計し、ログイン頻度の推移を表示

#### 管理者: 生徒一覧
- [ ] **REQ-13:** 生徒一覧をテーブル形式で表示する（名前、メール、入会日、進捗率、チャーンリスクレベル、最終ログイン日）
- [ ] **REQ-14:** 名前・メールアドレスでのテキスト検索ができる
- [ ] **REQ-15:** チャーンリスクレベル（高/中/低）でフィルタリングできる
- [ ] **REQ-16:** 各列でソートできる（名前、入会日、進捗率、チャーンリスク、最終ログイン日）
- [ ] **REQ-17:** ページネーション（1ページ20件）を実装する
- [ ] **REQ-18:** 行クリックで生徒詳細画面へ遷移する

#### 管理者: 生徒詳細
- [ ] **REQ-19:** プロフィールセクション（名前、メール、年齢、性別、職業、住所、入会日、入会からの経過日数）を表示する
- [ ] **REQ-20:** AIチャーン予測スコアを視覚的なゲージ（0〜100）で表示する。スコアに応じて色分け（低リスク: 緑、中リスク: 黄、高リスク: 赤）
- [ ] **REQ-21:** チャーン予測の根拠となる行動指標（ログイン頻度、課題提出間隔、セミナー参加率）を表示する
- [ ] **REQ-22:** 進捗タイムライン（入会日→各課題の完了日→現在地）を時系列で表示する
- [ ] **REQ-23:** 活動履歴（ログイン、課題提出、セミナー参加のログ）を新しい順に表示する

#### 講師: レビュー一覧
- [ ] **REQ-24:** 「未レビュー」「レビュー済み」のタブ切替で課題提出一覧を表示する
- [ ] **REQ-25:** 各カードに生徒名、レッスン名、提出日時、ステータスを表示する
- [ ] **REQ-26:** 未レビュータブにバッジで件数を表示する
- [ ] **REQ-27:** カードクリックでレビュー詳細画面へ遷移する

#### 講師: レビュー詳細
- [ ] **REQ-28:** 提出内容（生徒名、レッスン名、提出日時、テキスト内容）を表示する
- [ ] **REQ-29:** フィードバック記入フォーム（テキストエリア + 任意の5段階評価）を表示する
- [ ] **REQ-30:** 送信ボタンクリックでレビューを保存し、ステータスをREVIEWEDに更新する
- [ ] **REQ-31:** 既にレビュー済みの場合、フィードバック内容を読み取り専用で表示する
- [ ] **REQ-32:** レビュー履歴（過去のフィードバック一覧）を表示する

#### 生徒: ダッシュボード
- [ ] **REQ-33:** 「入会〇日目」のバナーを画面上部に表示する。計算: 現在日 - enrolledAt
- [ ] **REQ-34:** コース別の進捗サマリーカード（コース名、進捗率プログレスバー、完了レッスン数/全レッスン数）を表示する
- [ ] **REQ-35:** 「次にやるべきレッスン」へのクイックアクセスリンクを表示する。判定: 未完了の最初のレッスン
- [ ] **REQ-36:** 直近の活動履歴（最新5件）を表示する

#### 生徒: コース一覧
- [ ] **REQ-37:** コースカード一覧を表示する（サムネイル、タイトル、説明、進捗率プログレスバー）
- [ ] **REQ-38:** カードクリックでカリキュラム画面へ遷移する

#### 生徒: カリキュラム
- [ ] **REQ-39:** セクション/レッスンの階層構造をアコーディオン形式で表示する
- [ ] **REQ-40:** 完了済みレッスンにチェックマーク、未解放レッスンにロックアイコンを表示する
- [ ] **REQ-41:** ステップバイステップ制御: 前のレッスンが完了するまで次のレッスンはロックされる
- [ ] **REQ-42:** レッスンクリックで動画レッスン画面へ遷移する（ロック中はクリック不可）
- [ ] **REQ-43:** コース全体の進捗率プログレスバーを上部に表示する

#### 生徒: 動画レッスン
- [ ] **REQ-44:** 動画プレイヤーを左カラムに表示する
- [ ] **REQ-45:** チャプターリスト（タイムスタンプ付き）を動画下に表示する。チャプタークリックで該当位置にジャンプする
- [ ] **REQ-46:** レジュームダイアログ:「前回 XX:XX まで視聴しました。続きから再生しますか？」を表示する。判定: lessonProgresses.watchedSeconds > 0 かつ isCompleted === false
- [ ] **REQ-47:** 動画再生位置を定期的に（10秒ごと）lessonProgressesに保存する
- [ ] **REQ-48:** 動画を最後まで視聴したらisCompletedをtrueに更新する
- [ ] **REQ-49:** 右カラムにカリキュラム進捗（現在のレッスンがハイライト）を表示する
- [ ] **REQ-50:** 課題付きレッスン（hasAssignment === true）の場合、動画下に課題提出フォームを表示する
- [ ] **REQ-51:** 課題提出フォーム: 課題説明文、テキストエリア、送信ボタンで構成する
- [ ] **REQ-52:** 課題送信後にトースト「課題を提出しました。講師のレビューをお待ちください」を表示する
- [ ] **REQ-53:** 既に提出済みの場合、提出内容とレビューステータスを表示する。レビュー済みの場合はフィードバック内容も表示する

#### セミナー一覧（共通）
- [ ] **REQ-54:** 「今後のセミナー」「過去のセミナー」のタブ切替で一覧を表示する
- [ ] **REQ-55:** 各セミナーカードに日時、タイトル、説明、場所、参加方法選択（オンライン/現地ボタン）を表示する
- [ ] **REQ-56:** 参加方法（オンライン/現地）を選択して「申し込む」操作で登録する
- [ ] **REQ-57:** 申込済みのセミナーは「申込済み（オンライン or 現地）」表示に変わり、「キャンセル」ボタンを表示する
- [ ] **REQ-58:** キャンセルボタンクリックで申込を取り消す
- [ ] **REQ-59:** 管理者ロールでは各セミナーの申込者数（オンライン/現地の内訳）を表示する

#### コース一覧（共通）
- [ ] **REQ-60:** コースカード一覧を管理者・講師ロールでも閲覧できる（読み取り専用）

### 拡張機能（v1 見送り / v2 候補）
- [ ] **REQ-X1:** バッジ・ガミフィケーション — デモ優先度が低い。データ構造にBadge/UserBadgeテーブルを将来追加可能な設計にしておく
- [ ] **REQ-X2:** メッセージング（DM/チャット） — 工数大、デモで見せても地味
- [ ] **REQ-X3:** お知らせ・通知機能 — 差別化にならない
- [ ] **REQ-X4:** ファイルアップロード（課題添付） — テキスト提出で十分デモできる
- [ ] **REQ-X5:** 決済連携 — デモでは不要
- [ ] **REQ-X6:** ログイン認証 — デモではロール選択で代替。本番ではSupabase Auth導入
- [ ] **REQ-X7:** SCORM対応 — 企業研修向け。スクール向けデモでは不要

## 6. UI/UX 要件 (UI/UX Requirements)

## 8. 非機能要件 (Non-Functional Requirements)
- **レスポンシブ対応:** PC閲覧が前提。最低限タブレット（1024px〜）でサイドバーが折り畳まれるブレークポイントを設ける。モバイル対応はv2
- **パフォーマンス:** シードデータ40名規模のため、パフォーマンス最適化は不要。ページネーションは生徒一覧のみ実装（20件/ページ）
- **アクセシビリティ:** 最低限のキーボード操作対応（Tab移動、Enter/Spaceでのボタン操作）。スクリーンリーダー対応はv2
- **データ:** ローカル開発はPostgreSQL（Docker）。seedデータで全チャートがリアルに見えるよう設計

## 9. デモ用シードデータ設計

### テーマ: Webマーケティングスクール「GROWTH ACADEMY」

### ユーザー
- 管理者: 1名（田中管理者）
- 講師: 2名（佐藤講師、鈴木講師）
- 生徒: 40名（リアルな日本人名、デモグラ情報をバラつかせる）

### デモグラ分布
- 年齢: 20代(30%)、30代(40%)、40代(20%)、50代(10%)
- 性別: 男性(55%)、女性(40%)、その他(5%)
- 職業: 会社員(50%)、自営業(20%)、フリーランス(15%)、学生(10%)、その他(5%)
- 地域: 東京(30%)、大阪(15%)、神奈川(10%)、その他全国に分散

### コース
- 「Webマーケティング完全マスターコース」（メインコース）
  - Section 1: マーケティング基礎（レッスン3本）
  - Section 2: SNSマーケティング（レッスン3本）
  - Section 3: SEO・コンテンツマーケティング（レッスン3本）
  - Section 4: 広告運用・分析（レッスン3本）
- 各レッスンに2〜4チャプター（タイムスタンプ付き）
- 一部レッスンにhasAssignment=true（各セクション1個、計4個）

### 進捗パターン
- 完了者: 5名（全課題クリア済み、チャーンリスク低）
- 順調な学習者: 15名（進捗50〜80%、チャーンリスク低〜中）
- 停滞者: 10名（進捗20〜40%で止まっている、チャーンリスク中〜高）
- 未着手/離脱気味: 10名（進捗0〜10%、チャーンリスク高）

### チャーンリスクスコア分布
- 低リスク（0〜30）: 20名
- 中リスク（31〜60）: 12名
- 高リスク（61〜100）: 8名

### セミナー
- 過去セミナー: 4件（申込データ付き、オンライン/現地比率おおよそ6:4）
- 今後のセミナー: 3件

### 課題提出・レビュー
- 提出済み課題: 30〜40件
- レビュー済み: 20件（フィードバックテキスト + 1〜5評価付き）
- 未レビュー: 10〜20件

### 活動ログ
- 各生徒に10〜50件のactivityLogs（LOGIN, LESSON_VIEW, ASSIGNMENT_SUBMIT, SEMINAR_REGISTER）
- 進捗パターンに応じてログイン頻度を調整（完了者: 高頻度、離脱気味: 低頻度）

### 離脱スコア計算ロジック（seed生成時に適用）
```
チャーン予測スコア =
  (1 - ログイン頻度正規化値) x 40
  + (課題提出間隔正規化値) x 35
  + (1 - セミナー参加率正規化値) x 25

ログイン頻度正規化: 直近30日のログイン日数 / 30 (0〜1)
課題提出間隔正規化: min(最終課題提出からの日数, 90) / 90 (0〜1)
セミナー参加率正規化: 参加セミナー数 / 全セミナー数 (0〜1)

スコア0〜30 → LOW
スコア31〜60 → MEDIUM
スコア61〜100 → HIGH
```

## 12. 備考・制約 (Constraints/Notes)

- **認証:** ローカル開発はミドルウェアで全リクエストをモックユーザー認証済みにする。ロール切り替えはZustandストアでロールを保持
- **動画:** HTML5 `<video>` タグ + カスタムコントロール。サンプル動画URLを使用。lessonProgresses.watchedSecondsはAPI経由で保存
- **グラフライブラリ:** Recharts（shadcn/uiと相性が良く、Next.jsのSSRにも対応）
- **開発環境:** Docker Compose でPostgreSQL起動、Prisma migrateでスキーマ適用、prisma db seedでseedデータ投入
- **チャーン予測スコア:** シードデータ投入時に事前計算。リアルタイム再計算はv2
