Phase A（フロントエンド）の各タスクを実行する際の動作手順：
- @rules/frontend/ 配下のルールを再確認する。
- **View コンポーネントの実装時は、`designs/` 配下の全成果物を参照してデザインを忠実に再現する:**
    - `designs/*.pen`: 画面デザイン。レイアウト、余白、色、フォントサイズ、コンポーネントの種類・バリアントを一致させる。
    - `designs/custom-styles.md`: カスタムスタイル仕様（カスタムカラー、アニメーション、グラデーション等）があれば従う。
    - `designs/assets/`: カスタム画像・アイコン・イラスト。`public/` にコピー済みのパスで参照する。
- **View コンポーネント実装後、デザインとの視覚比較を行う:**
    1. Pencil MCP の `get_screenshot` で該当画面のデザインスクリーンショットを取得する。
    2. `npm run dev` でアプリを起動し、Playwright で同じ画面のスクリーンショットを取得する。
    3. 両方の画像を比較し、差異（色・余白・フォントサイズ・配置・コンポーネント種別等）を特定する。
    4. 差異があればコードを修正し、再度スクリーンショットを撮って比較する。一致するまで繰り返す。
- `edit` を使用して、コードを小さな単位で段階的に実装する。
- 実装直後に `shell` で `npx tsc --noEmit` を実行し、型安全性を確認する。
- 対応するテストファイルが存在する場合は、`npm test <path>` を実行する。
- コマンドが失敗した場合は、`read` でエラー出力を確認し、コードを修正して、合格するまでリトライする。
- 各タスクが成功するたびに `git commit` を行い、進捗を確定させる。

## Phase A 全タスク完了後の動作確認

全タスク完了後、Playwright を使って実際にアプリを操作し動作確認を行う:
1. `npm run dev` でアプリをバックグラウンド起動する。
2. `.tasks.md` の Phase A 動作確認チェックリストの各項目について、Playwright でページ遷移・クリック・フォーム入力等を実行する。
3. 各ステップで `page.screenshot()` を取得し、コンソールエラーがないか確認する。
4. 問題を発見した場合は、内容を記録し、コードを修正して再確認する。問題がなくなるまで繰り返す。
5. 全項目パス後、動作確認の結果をユーザーに報告する。
